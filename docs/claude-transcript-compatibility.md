# Claude Code transcript compatibility

This document records black-box compatibility probes for histories generated by
Anima and resumed by Claude Code. A version is not writable merely because
Anima can read its existing transcripts.

## Claude Code 2.1.220

Probe environment: macOS on arm64, 2026-07-29.

### Isolation

The probe used a disposable `CLAUDE_CONFIG_DIR` and disposable working
directory. It did not write to the normal Claude configuration or project
directories. The repeatable integration test accepts authentication only
through the environment and does not copy a provider credential file.

Existing local sessions were inspected only for structural field names and
record shapes. Conversation text was not captured in the fixture.

### Project routing

Claude stores a project transcript at:

```text
<CLAUDE_CONFIG_DIR>/projects/<project-key>/<session-uuid>.jsonl
```

For this version on macOS, `<project-key>` is the real, absolute working
directory with every character outside `A-Z`, `a-z`, `0-9`, and `-` replaced
by `-`. Dots, underscores, and path separators therefore become hyphens.
Callers must resolve filesystem aliases first; on macOS, `/var/...` may resolve
to `/private/var/...`, and Claude indexes the latter.

### Validated template

A generated history needs one parent-linked JSONL record per visible message.
The validated template uses:

- A `user` record with the session UUID, cwd, version, record UUID, timestamp,
  prompt UUID, and `{ role: "user", content: <text> }`.
- An `assistant` record with the same common metadata and a complete Messages
  API-shaped envelope containing one `text` block, terminal stop metadata, and
  zeroed usage metadata.
- Each record's `parentUuid` set to the preceding record UUID; the first is
  `null`.

A two-record generated transcript resumed successfully without queue-operation,
attachment, file-history, title, mode, permission-mode, system, or last-prompt
records. Claude added its normal auxiliary records when it appended a new turn.

The sanitized known-good template is
[`test/fixtures/claude/2.1.220/generated.jsonl`](../test/fixtures/claude/2.1.220/generated.jsonl).
`encodeClaudeTranscript` emits that versioned shape and fails closed for every
other Claude version.

### Resume, rendering, and model visibility

Pass:

1. Write one generated user record and one generated assistant record under an
   isolated project key.
2. Run `claude --resume <session-uuid>` in the recorded working directory.
3. Confirm the interactive TUI renders both imported messages in their original
   roles and order.
4. Ask the next model turn to return the two prior messages without including
   either sentinel value in the verification prompt.
5. Confirm it returns both values exactly.
6. Read the appended transcript through `readClaudeSession`.
7. Confirm imported and new messages remain role-complete and parent-linked.

The generated history is visible in the TUI, model-visible on the next turn,
durable after Claude exits, and readable by Anima after Claude appends to it.

### Capability decision

| Capability | 2.1.220 |
| --- | --- |
| Offline transcript creation | Yes |
| `claude --resume <uuid>` | Yes |
| Imported turns visible in TUI | Yes |
| Imported turns model-visible | Yes |
| New turns append to the generated chain | Yes |
| Role-complete standalone Anima readback | Yes |

Claude Code 2.1.220 is compatible with the versioned transcript template. This
unblocks the Codex-to-Claude encoder, but the production CLI remains disabled
until Anima also has the durable canonical archive, projection transaction, and
atomic native writer required by the architecture.

### Repeatable integration test

The networked check is opt-in:

```text
ANIMA_CLAUDE_INTEGRATION=1 \
CLAUDE_CODE_OAUTH_TOKEN=... \
ANIMA_CLAUDE_COMMAND=/path/to/claude \
npm test
```

`ANTHROPIC_API_KEY` may be supplied instead when that is the configured Claude
authentication method. Normal `npm test` skips the live check and runs the
offline template and round-trip coverage.
